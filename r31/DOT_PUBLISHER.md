# R31 publisher handoff (staging, not activated)
Same five Dots, no per-device cash or holdings. Dot 1 market/news; 2 discovery; 3 risk; 4 strategy; 5 consolidate and publish. Before each hour, all read the latest broadcast and strategy-universe.json, not a customer ledger. Dot 5 generates account-neutral BUY/HOLD/SELL/WATCH/NO_TRADE/DATA_GAP with exact identity, price EUR, actual observation time, URL, reason and optional sell fraction. No amount/cash fields. Every previously BUY-recommended coin may be held somewhere: review all strategy-universe LONG and EXIT intents, not merely current reference holdings. For EXIT, repeat a fresh SELL instruction where appropriate so offline clients can exit when online again; without fresh price DATA_GAP and keep exit intent. Unknown price must not be guessed. A new BUY can explicitly change thesis/intent. Missing coverage is automatically DATA_GAP, not an assumed sell.
Only Dot5 may publish. The publisher module and CLI validate and create immutable sequence, pointer and universe in a single GitHub commit, using non-force update and readback. Connector alternative: get HEAD via commits endpoint, read pointer/universe at SHA, build same signal schema, create blobs (verify returned hashes), tree, commit, update_ref expected_sha=HEAD force=false, verify. No automatic publisher scheduled yet. Do not activate until staging E2E succeeds and the R30 cutover is separately confirmed; no modification of R30 or its five tasks in this phase.
CLI only with separately authorized publishing credential in local secret storage: node r31/publish.mjs <validated-signal-input.json>. No real money, no customer account fields, no arbitrary repository/branch overrides. Feed clients use read-only credentials or anonymous GET. The public strategy feed is not an authenticated trading venue; no real-money signing, quote or settlement integration.
