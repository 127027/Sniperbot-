# R31 – aktueller Einstieg: unabhängige Geräte

Die neue Mehrgerätearchitektur ersetzt den zentralen Staging-Entwurf (unten nur Historie). [Vertrag](MULTI_DEVICE.md). **Start:** `node r31/device-server.mjs` (Node 22+); `http://127.0.0.1:8787`. Je Installation eigener lokaler Ordner (`R31_ACCOUNT_DIR`, Standard im Benutzerverzeichnis `.r31-paper-device`), je Konto ein Prozess; optional `R31_PORT` für mehrere lokale Konten. Neues Konto startet mit 0 EUR Testgeld und deaktivierten Neukäufen; lokal einzahlen, Limits setzen, Kauf erlauben. Nur GET zum öffentlichen GitHub-Feed alle fünf Minuten; optional lokaler read-only GitHub-Token `R31_GITHUB_READ_TOKEN`, niemals ein Write-Token für Clients. Bei vielen Geräten hinter gleicher IP greifen gemeinsame GitHub-Limits; für zuverlässigeren Empfang separate autorisierte Read-Zugriffe prüfen. Publisher ist noch NOT_PUBLISHING. Keine R30-Übernahme, keine historischen Käufe, keine Aktivierung der Dots, keine native Handy-App, kein Echtgeld. Alte `server.mjs` ist nur historischer Prototyp, nicht für unabhängige Konten benutzen.

# R31 – lokales Paper Control Center (Phase 1)
Entwicklungsbranch, getrennt vom aktiven R30. R30 bleibt unverändert und führt das echte (virtuelle) Journal weiter. R31 liest dessen letzten SHA-geprüften Finalbericht, zeigt Positionen/Handelsjournal und veröffentlicht **nur vorbereitete Paper-Einstellungen** auf diesem Branch. Keine R31-Dots lesen die Einstellungen bisher; keine automatisierte R31-Ausführung, keine Echtgeld-/PayPal-Funktion. Keine Veröffentlichung privater Guthaben oder Schlüssel (Repository öffentlich).
## Windows
Node.js 22+ installieren. Branch separat klonen:
```powershell
git clone --branch codex/r31-control-center-paper https://github.com/127027/Sniperbot-.git R31
cd R31
node --test r31/policy.test.mjs
node r31/server.mjs
```
Öffne http://127.0.0.1:8787 im Browser. Lesen funktioniert für öffentliche GitHub-Daten ohne Token, unterliegt GitHub-Limits. Schreiben erfordert eigenen auf dieses Repository beschränkten GitHub-Zugriff (Contents read/write), z.B. einen Fine-grained PAT, nur lokal als Umgebungsvariable R31_GITHUB_TOKEN setzen. Niemals Token in Git, HTML, Chat oder Kommandohistorie speichern. Token mit lokaler sicherer Secret-Verwaltung bereitstellen. Kein OpenAI- oder Marktanbieter-API-Key. Keine laufenden Kosten garantiert; GitHub-Limits und Nutzungsbedingungen gelten.
## Vertrag
r31/controls.json ist der versionierte, centgenaue Steuervertrag. max_invest_cents ist maximal offene Anschaffungskosten, nicht Einzahlung oder Gesamtvermögen. stake_cents ist exakter Einsatz je neuem Coin. allow_new_buys pausiert ausschließlich zukünftige Käufe (in R31 noch nicht angebunden); keine Zwangsverkäufe bei niedrigerem Limit. Reduziertes Limit blockiert neue Käufe. Erhöhtes Limit schafft kein neues Cash. GitHub-Blob-SHA und revision verhindern lost update; Readback erforderlich. policy.mjs enthält reine Admission-Guard-Logik, keine Ausführung. R30-Read-only-Ansicht hat keinen Schreibpfad zum R30-Branch.

## Isolierter Modell-Executor (noch nicht angeschlossen)
`paper-engine.mjs` ist eine reine Funktion für R31-Modellzyklen. Kein Zugriff auf GitHub oder Markt, keine automatische Ausführung. Er prüft Konfigurationsrevision, Zielstunde, genaue Coin-Identität, explizite Bewertung aller Positionen, doppelte Entscheidungen, Preisbeobachtung, Herkunft, Cash, Kostenbasis und exakten Stake. Verkäufe vor Neukäufen, Pause blockiert nur neue Käufe. Unbekannte Marks machen Gesamt-PnL unbekannt statt fiktiv null. Synthetische Tests belegen Mechanik, nicht reale Marktqualität. Ein R31-Echtbetrieb oder eine Übernahme des R30-Ledgers ist noch nicht aktiv. Vor Umschaltung sind tatsächlicher Dot-Entscheidungsvertrag, sichere atomare Ledger-Persistenz und End-to-End-Test erforderlich.
