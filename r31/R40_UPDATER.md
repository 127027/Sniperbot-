# R40 device updater (development branch, not released)
Desktop Windows/Linux/macOS: Node 22+, start once with node r31/launcher.mjs instead of device-server.mjs. Existing R31_ACCOUNT_DIR remains unchanged (default ~/.r31-paper-device). The button checks only the fixed main release manifest r40/releases.json, verifies SHA-256 and exact allowlist from immutable commit, stages separately; stops polling, backs up local account, releases lock, starts new version, checks ready IPC before activating; on startup failure restarts previous code without restoring stale account. No auto updates. No live feed changes. Manifest HTTPS/GitHub repository trust, not an independent signed release.
Android: same app package only, download fixed commit APK path, verify size SHA256 + version + package + installed signing certificate; private backup, then Android install confirmation. User may need to allow installation from this source. Android may require manual app reopen/restart background service. Old per-build test certificates generally cannot be upgraded; never uninstall to bypass. Release requires durable private signing key compatible with installed version; CI default test builds NOT production upgrades. iPhone/iPad native app not present; App Store/TestFlight or permitted Apple distribution necessary; no self-install native binary from GitHub. macOS desktop uses launcher, not a native signed macOS app.
Release intentionally not published yet; fixed manifest not created on main until approved test build and signing. Initial bootstrap required. No secrets committed. Tests cover manifest/path/hash/version; actual restart and physical Android installation still require integration check.

R41: explicit NO_RELEASE_AVAILABLE manifest is published on main; no Android package approved, no signature bypass. UI displays clean paper epoch and correct release number. Existing R40 installation continues to read the reset ledger without reinstalling.
