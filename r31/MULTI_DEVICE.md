# R31 Multi-device broadcast contract
User approval 25 Nov 2026. The same five Dots are a single strategy publisher; there is **no central customer portfolio**. Every device has its own independent local account, cash, stake, limit, trade IDs, holdings, funding and cursor. No account ID, balance, deposit, withdrawal, wallet or secret in the public GitHub signal feed. No client write token required; local settings never uploaded. A new installation has zero paper funds and no positions, starts with purchases paused, and only processes newly published, unexpired signals after joining. SELL/HOLD absent -> ignored; BUY already owned -> HOLD; missing held coin -> DATA_GAP, never automatic sale. Each device interprets identical signals with its own current stake and limits. Sell first, then buy, no forced trades. Offline gaps visible; expired signals never replayed; historical missing sell is not retroactively booked. Keep reference strategy exit coverage for all previously issued BUYs even if reference budget full; portfolio-specific choices belong on devices, not publisher. Future signals must include explicit exit intent for previously recommended coins, or DATA_GAP if unknown, so independent portfolios do not get stranded. Every device may differ because of join time, funding, local limits, pauses and connectivity.
Publisher (not enabled yet): immutable r31/broadcast/signals/0000000001.json, monotonic sequence and previous_blob_sha, full hourly UTC target, publication at/after target within ten minutes, expiration max 15 min after target, exact chain/contract and observed indicative EUR prices, reasons, links, no account amounts. Dot5 alone publishes via atomic GitHub tree/commit/CAS with latest.json pointing at immutable blob, no overwrite or force. All five roles analyze the shared strategy universe, not specific customers. Never claim this is connected to active R30; R30 stays untouched. The pointer initially NOT_PUBLISHING; clients can run but won't execute until a new valid signal is published. Signal feed is pinned to commit and Git blob hashes; no independent publisher cryptographic signature yet. Add trusted publisher signing and verified owner key before any real-money work.
This is simulated paper funding only. Devices must not share the same local directory; single writer lock and atomic rename persist ledger and cursor together. Stale lock: manually check no process is alive before removing. No native Android/iOS yet. Mobile background restrictions require dedicated local execution/service design; no claim unattended phone trading. PayPal/real deposits and withdrawals require separate provider/account integration and authorization; never store funds/credentials on GitHub.
