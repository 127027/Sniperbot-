# R43 Android release signing
No signing key is stored in GitHub source, chat, artifacts, or logs. Owner must recover the private key used by the installed APK if available; a public certificate cannot reconstruct it. Old ephemeral CI keys were not uploaded. If unrecoverable, there is no in-place upgrade from that installation. Preserve that app and its data; migration/reinstall requires a separate explicit decision and backup/export, which is not provided by old builds.
For future releases create a dedicated private keystore locally (for example keytool -genkeypair -keystore sniperbot-release.jks -alias sniperbot -keyalg RSA -keysize 3072 -validity 10000; choose strong passwords). Keep an encrypted backup. Configure repository Actions secrets R43_ANDROID_KEYSTORE_B64, R43_ANDROID_STORE_PASS, R43_ANDROID_KEY_PASS, R43_ANDROID_ALIAS via GitHub settings, and repository variable R43_ANDROID_CERT_SHA256 (lowercase hex of certificate, no colons). Never paste passwords or keystore contents in chat. Certificate fingerprint can be obtained from keytool -list -v -keystore ... and normalized, or apksigner verify --print-certs on a signed APK. The pin is public information.
Manual workflow R43 signed Android release: select reviewed immutable source SHA from updater branch, first run with publish=false, inspect tests/build/certificate. Only publish=true after verification and owner approval. It rejects unsigned/test fallback, different pin, downgrade or rotation, packages outside com.r31.paperbot. Publish uses a non-force atomic push containing immutable APK commit and manifest commit; does not touch the trading branches or local accounts. An Android install confirmation is still required; background service may need manual restart. The currently installed R40 can read compatible manifests, but an old mismatched signer cannot be bypassed.
