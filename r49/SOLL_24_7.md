## Architecture and honest capability
Current task scheduler supports at most one scheduled start/hour/task; cannot configure guaranteed 60-minute runtime, trigger an unrestricted internal loop, or guarantee exactly-on-time starts. R49 is a partial implementation of the target, not an always-on runtime. No artificial sleeping, idle time, claiming full WWW coverage, fake timestamps or invented activity. When actual runtime ends, persist remaining queue and resume next allowed execution. Genuine continuously-running AI workers require a supported always-on execution architecture; not proven available under current no-new-API constraint. Do not circumvent limits.

If absent, initialize from registry and open leads. First save a useful incremental checkpoint as soon as actual findings available, then continue with next unreviewed batch while execution permits. After each batch save latest and immutable batch file r49/work/dot-N/batches/<actual-UTC-timestamp>-<unique-run-suffix>.json together atomically with CAS/nonforce ref and blob readback. If head changes, refetch and merge own updated data without overwriting peers, retry within actual budget. Use unique path; never rewrite immutable batch; pointer includes path/SHA. Update own partial report by CAS before closing, then continue work if possible. Dot5 final immutable. Final prose not substitute for write/readback.
