# Canonical target — hourly decisions, continuous research, daily learning
User clarified 26 November 2026. This document defines the product objective, superseding two-batch test counts as a measure of product success. It is not a runtime or trading enablement change.
## Target
Five research workers jointly maintain continuous market awareness (new meme tokens/pools, price/volume/liquidity, original news/social catalysts, risk and held positions). Every full hour Europe/Berlin, publish one coherent point-in-time report of BUY, HOLD, SELL, NO_TRADE/WATCH with exact chain/token/pool identity, evidence/source times, thesis, entry/exit, risk and execution status. Use the available paper capital, no forced trades. The local bot executes only authorized paper orders; no real funds. New events occurring between hours should be observed promptly and influence the next report. Preserve prior positions and decisions across scans. GitHub is transport, durable knowledge and audit, not a substitute for decisions.
## Independent comparison
Independent GPT market scan at the same hourly cutoff, using only evidence available before cutoff and its own separate paper account; no access to the dots' decisions before recording comparator. Same starting cash, position sizing, modeled fees/slippage, capital and risk constraints. Do not claim that the current chat automatically runs continuously or that a sixth scheduled task is available. Separate actual run, manual review and retrospective reconstruction. Existing no-new-API/key requirement remains. No silent increase in scope or external billing.
## Daily learning
For each fixed 24h window, build a source-grounded universe of observable meme tokens/pools with >100% rise during that window, including newly launched coins and duplicate tickers resolved by chain and contract. Record metric definition (e.g. earliest observable price to later peak or close; distinguish), source coverage, launch/observation times, liquidity, feasibility, risk and data gaps. Compare time-ordered decisions and actual simulated fills against first feasible entry and exit opportunities. Separate missed discovery, missed catalyst, late discovery, risk rejection, missed entry, missed exit, lack of capital, and unobservable/untradable outcomes. Hindsight winners are discovery/learning benchmark, not proof every winner should have been bought. Also assess false-positive buys, losses, net return, drawdown and fees; no look-ahead or survivorship bias. Derive hypotheses from observed evidence, replay on later unseen windows before promoting changes. Keep raw evidence and learning history.
## Acceptance gates
1. End-to-end hourly report + valid paper lifecycle and auditable decisions, including held positions, not mere package counts.
2. Source freshness/coverage and event detection latency measured, full-hour research coverage not claimed from wall-clock alone.
3. Independent hourly comparator and 24h winner/loser review with feasible-opportunity coverage and missed-opportunity diagnosis.
4. Runtime reality: current scheduled tasks start at most hourly through exposed controls; observed R50 runs last seconds, not 60 minutes. No configuration exposed to guarantee continuous GPT execution or immediate event detection. Repeated prompt tuning cannot establish this architecture. A continuous event collector and supported continuous model execution would be separate prerequisites; no new API/keys or unsupported workaround without user decision. Hourly batch fallback is explicitly a reduced-scope mode.
