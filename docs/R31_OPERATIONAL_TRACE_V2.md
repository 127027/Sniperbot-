# R31 operational trace v2 — approved 27 November 2026
Every actual operational action must be accounted for in chronological order: seq, kind, action, purpose (short task justification, not private reasoning), tool, exact non-secret request or search query, status, actual result, exact error or NONE, next action, observed_at UTC if known or null. Each independent source query/read receives its own entry; do not group several calls into one. Report skipped/unexecuted steps explicitly, never as successful. Record source URLs and actual returned evidence; historical dates are not current quotes. Link each assessed row to source step_refs. End with REPORT step, stop_reason and next_work, blockers, actual number sighted. Report gaps rather than invent logs, tool errors, timestamps, hidden termination causes or completed actions.
The independent controller records authoritative scheduler start/end, raw report, SHA, terminal status. A self-reported trace is not an instrumented tool log; if a run is interrupted before return, exact missing internal actions cannot be recovered from scheduler metadata. Keep raw captures immutable. Strictly unwrap only full escape wrapper or JSON code fence for parsing, preserve original bytes. V1 accepted as legacy structure, never retroactively fabricate steps. V2 missing/invalid steps or no actual source attempt reported = incomplete. Structural acceptance is not verified market evidence or qualified BUY. Independent checks of sources and actual risks/costs remain necessary. No orders, wallet, production or main edits.
