# R31 terminal worker diagnosis and bounded continuation
The user requires a mandatory reason for ending research. The controller must not accept an incomplete worker as a success. Existing scheduler exposes recorded_status and result text, not internal termination reason, process logs or a way to force uninterrupted execution. A completed platform run is not proof of task completion. Do not manufacture a root cause.
Each terminal worker receives a deterministic failure classification from observed run state and committed evidence. Missing checkpoint/final and checkpoint-without-final are distinct. These labels identify the violated lifecycle step, not the hidden internal reason. Continue from last verified next_work. Record exact tool calls, failures, alternatives, actual next unfinished action, proposed repair and acceptance. If worker produces no final, controller records independent diagnosis explicitly as controller-generated, never impersonates worker.
The collector now produces compact, disjoint six-contract packets by role, tied to real snapshot and runtime. These are research inputs, never BUYs. At each invocation prioritize actual candidate review and immediate persisted small batch, then further work. Do not repeatedly read policy files or reproduce successful 404 tests. Full hourly and 24h behavior still unverified. Real worker invocation and independent report readback required.
